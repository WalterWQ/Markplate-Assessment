# Marketplace 

## Project Overview

Marketplace is a peer-to-peer marketplace built using .NET MAUI.  
Users can list items (e.g. tools), discover nearby items using location-based search, request rentals, and manage rentals.

Example use case:
- A user lists an item (e.g. a drill)
- Another user searches for nearby items
- They request a rental
- The owner approves or rejects

---

## Setup Instructions

### Prerequisites

- .NET 10 SDK
- Docker Desktop
- Visual Studio Code with C# Dev Kit
- Android Emulator or Windows target

---

### 1. Clone Repository

Clone the repository from GitHub.

### 2. Open Repository in Visual Studio

Open the solution file in Visual Studio.

### 3. Restore Dependencies

Run:

dotnet restore

### 4. Clean Project

Run:

dotnet clean

### 5. Build Project

Run:

dotnet build -c Debug

---

## Running the Application

### 1. Select Startup Project

Set the MAUI app project as the startup project.

### 2. Select Target

Choose Android Emulator or Windows target.

### 3. Run Application

Press Start/Run in Visual Studio.

## API Endpoint Documentation

API documentation:

https://set09102-api.b-davison.workers.dev/

Main endpoints:
- POST /auth/token – Login
- POST /auth/register – Register
- GET /users/me – Current user profile
- GET /items – View items
- POST /items – Create item
- PUT /items/{id} – Update item
- GET /items/nearby – Find nearby items
- POST /rentals – Request rental
- GET /rentals/incoming – Incoming rental requests
- GET /rentals/outgoing – Outgoing rental requests
- PATCH /rentals/{id}/status – Update rental status

## Architecture Overview

### MVVM Pattern

- Views contain XAML UI
- ViewModels contain commands and UI logic
- Models represent application data

### Repository Pattern

Repositories abstract data access from the rest of the application.

Implemented repository examples:
- ItemRepository
- IItemRepository

### Service Layer

Services separate business logic from ViewModels.

Implemented services:
- ApiService
- IApiService
- LocationService
- ILocationService
- RentalService
- IRentalService

### Location-Based Discovery

The application supports nearby item discovery using latitude, longitude, and a configurable radius.  
Location access is abstracted through LocationService so GPS logic is not placed directly in the ViewModel.

### Rental Workflow

Rental requests support workflow states such as:

- Requested
- Approved
- Rejected
- Returned
- Completed

Owners can approve or reject requests.  
Borrowers can mark approved rentals as returned.  
Owners can complete returned rentals.

## Testing

### Testing Approach

The tests use the Arrange-Act-Assert pattern.

Test coverage includes:
- Repository logic
- Nearby item filtering
- Rental workflow behaviour
- Database fixture setup
- Mocked GPS/location behaviour
- Mocked rental API behaviour

### DatabaseFixture

DatabaseFixture uses an in-memory database to provide repeatable test data.

### Mocking External Dependencies

External dependencies are mocked using test doubles:
- GPS/location is mocked in ViewModel-style tests
- Rental API behaviour is mocked in service tests
- Database access is tested using EF Core InMemory
